# Implementation Plan

> 今回はサーバー、API、データベース、外部AIを実装せず、ブラウザ内のモックデータだけで操作できるモックアップを作る。状態は同一ページセッション中に保持し、再読み込み時に初期状態へ戻す。

- [x] 1. モックアップの実行・検証基盤を整える
- [x] 1.1 既存のVite・React構成をモックアップ用の実行基盤として整える
  - サーバールート、API通信、データベース、外部AIを追加せずに開発・型検査・本番ビルドを実行できる状態を維持する
  - DOM上の画面状態と利用者操作を検証できるテスト環境を追加する
  - 開発起動、型検査、テスト、本番ビルドの各コマンドが実行可能になっていることを完了条件とする
  - _Requirements: 7.1, 7.5_

- [x] 1.2 時刻と回答進行を決定的に制御できるモック機構を用意する
  - ログインロックの10分とセッションの24時間を実時間待機なしで境界直前・境界ちょうどへ進められるようにする
  - 回答チャンクの進行、完了、回答不能、途中失敗、中断を任意の時点で確定できるようにする
  - 自動テストから時刻と回答状態を手動で進め、各中間状態を観測できることを完了条件とする
  - _Requirements: 1.4, 1.5, 1.6, 1.8, 1.9, 2.3, 2.4, 2.7, 2.8_

- [x] 1.3 Unicode入力境界の共通処理を用意する
  - 複合絵文字と結合文字を1書記素、改行を1書記素として数える
  - 空白または改行だけの入力を空として判定し、指定上限を超える書記素を入力へ反映しない
  - 画面制御を経由しない上限超過値も送信または保存しない
  - 0・1・400・401および0・1・1000・1001の境界を自動テストで確認できることを完了条件とする
  - _Requirements: 2.1, 2.5, 2.6, 2.12, 5.2, 5.5, 5.6_

- [x] 2. ブラウザ内モック状態と5画面の骨格を作る
- [x] 2.1 認証・セッション・ロック状態を扱うモックを用意する
  - 一般社員と管理者社員の固定テスト用資格情報、失敗回数、ロック期限、セッション開始時刻を扱う
  - 同一ページセッション中は画面遷移後も変更を保持し、再読み込み時は初期状態へ戻す
  - 一般社員と管理者社員の資格情報、および任意のロック・セッション状態をテストから再現できることを完了条件とする
  - _Requirements: 1.4, 1.5, 1.6, 1.7, 1.8, 1.9, 1.13_

- [x] 2.2 FAQ状態と回答シナリオを扱うモックを用意する
  - FAQの初期データ、空状態、登録、修正、完全一致検索を扱う
  - FAQに根拠がある正常回答、複数FAQ回答、回答不能、生成失敗を決定的な入力またはシナリオで再現する
  - FAQ以外の情報を回答へ加えず、登録・修正したFAQを後続回答の候補にできる状態を完了条件とする
  - _Requirements: 2.2, 2.7, 2.8, 2.9, 4.2, 5.3, 5.4, 5.7, 5.8_

- [x] 2.3 社員別の履歴と評価状態を扱うモックを用意する
  - 質問日時、質問、回答または回答不能案内、任意のGood・Bad評価を社員ごとに分離して扱う
  - 回答単位で一度だけ評価でき、評価集計を利用者向け状態として提供しない
  - 利用者を切り替えても他社員の履歴を取得できないことを自動テストで確認できる状態を完了条件とする
  - _Requirements: 3.2, 3.3, 3.4, 6.4, 6.5, 6.6_

- [x] 2.4 5画面のルートとアクセス判定の骨格を用意する
  - ログイン、質問、履歴、FAQ閲覧、FAQ管理の各画面に固有の表示先を用意する
  - 未認証、一般社員、管理者社員ごとに、ログインへの移動、権限拒否、表示許可を判定する
  - 各役割で直接アクセスした際に設計どおりの画面または拒否結果が表示されることを完了条件とする
  - _Requirements: 1.10, 1.12, 5.9, 7.1, 7.4_

- [x] 3. ログインから認証体験を完成させる
- [x] 3.1 ログイン画面と正常・異常の送信体験を作る
  - 社員IDと伏字表示のパスワードを受け付け、送信中の重複操作を防ぐ
  - 一般社員と管理者社員の有効な資格情報で質問画面へ移動し、無効時は共通の失敗文言を表示する
  - 有効・無効なログインを画面から操作し、未認証時に社内情報が表示されないことを完了条件とする
  - _Requirements: 1.1, 1.2, 1.3, 1.13, 7.4_

- [x] 3.2 連続失敗と10分間のログインロックを再現する
  - 同一社員IDの1〜4回目の失敗、5回目のロックと失敗回数リセットを扱う
  - ロック中は正しいパスワードも拒否し、10分ちょうどで受付を再開する
  - 解除後の失敗が新しい1回目になり、成功時は失敗回数がリセットされることを画面とテストで確認できることを完了条件とする
  - _Requirements: 1.4, 1.5, 1.6, 1.7_

- [x] 3.3 24時間セッションと認証操作を作る
  - ログイン成功から絶対24時間だけ有効なセッション判定、ログイン済み利用者のログイン画面アクセス、ログアウト動作を提供する
  - 期限切れ後の次回保護画面アクセスではログイン画面へ移動し、社内情報を表示しない
  - セッションの24時間未満・ちょうど、ログアウト、保護画面への直接アクセスを決定的に確認できることを完了条件とする
  - _Requirements: 1.8, 1.9, 1.10, 1.11, 1.12, 7.4_

- [x] 4. 認証済みの共通体験と質問画面を完成させる
- [x] 4.1 認証済み4画面の共通ナビゲーションを作る
  - 質問、履歴、FAQ閲覧、FAQ管理の各画面に「質問」「履歴」「FAQ閲覧」「ログアウト」を表示する
  - 質問、履歴、FAQ閲覧では視覚的かつプログラム上判別可能な現在地を示し、FAQ管理ではいずれも現在地にしない
  - FAQ管理を共通項目に含めず、FAQ閲覧画面の管理者専用操作を移動入口とする
  - 各項目が画面遷移または認証操作へ接続可能な共通の操作入口として表示されることを完了条件とする
  - _Requirements: 4.3, 4.4, 5.1, 5.9, 7.2, 7.3_

- [x] 4.2 質問入力と送信の境界を作る
  - 空、空白のみ、改行のみでは送信を無効にし、1〜400書記素では送信可能にする
  - 400書記素で正式文言のツールチップを文字数カウンターへ関連付け、400未満では表示しない
  - 401書記素目を入力へ反映せず、画面制御を経由しない超過送信を拒否し、生成中の再送信を防ぐ
  - キーボード操作と支援技術からも文字数上限を認識できる質問フォームが表示されることを完了条件とする
  - _Requirements: 2.1, 2.5, 2.6, 2.10, 2.11, 2.12_

- [x] 4.3 モック回答のライフサイクルを表示する
  - 有効な質問の送信後に回答を順次追加表示し、完了時に回答全体を表示する
  - 定義済みシナリオで回答不能案内、生成失敗と再試行を再現し、処理中の同一操作を防ぐ
  - 成功、回答不能、生成失敗、中断の各結果を画面上で決定的に再現できることを完了条件とする
  - _Requirements: 2.2, 2.3, 2.4, 2.7, 2.8, 2.9_

- [x] 4.4 回答出典を設計どおり表示する
  - 回答本文の後に、実際に使用したFAQの質問だけを重複なく表示する
  - 回答生成中、回答不能、生成失敗では出典を表示しない
  - 単一FAQと複数FAQのシナリオで、完了後だけ正しい出典一覧が表示されることを完了条件とする
  - _Requirements: 2.2, 2.4, 2.7, 2.8, 2.9_

- [x] 4.5 回答へのGood・Bad評価操作を作る
  - 回答生成中は操作不可とし、完了した未評価回答にだけ両操作を表示する
  - 初回評価後は選択内容と受付完了を表示し、両操作を非活性にして再操作エラーを表示しない
  - 一回答につき一度だけ評価状態が生成され、集計や分析結果が表示されないことを完了条件とする
  - _Requirements: 6.1, 6.2, 6.3, 6.4, 6.5, 6.6_

- [x] 5. 履歴とFAQの各画面を作る
- [x] 5.1 (P) 本人の質問履歴画面を作る
  - 本人の履歴を新しい順に、質問日時、質問、回答または回答不能案内、送信済み評価とともに表示する
  - 履歴がない場合は「質問履歴はありません」と表示する
  - 一般社員と管理者社員のどちらでも他社員の履歴が表示されないことを独立した画面テストで確認できることを完了条件とする
  - _Requirements: 3.1, 3.2, 3.3, 3.4_
  - _Boundary: 履歴画面_
  - _Depends: 2.3, 2.4, 4.1_

- [x] 5.2 (P) FAQ閲覧画面を作る
  - 登録済みFAQの質問と回答、およびFAQがない場合の空状態を表示する
  - 一般社員には管理操作を表示せず、管理者社員には新規登録と各FAQの編集操作を表示する
  - 管理者操作から指定された新規登録・編集モードへ移動でき、削除操作が存在しないことを完了条件とする
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 5.1, 5.10_
  - _Boundary: FAQ閲覧画面_
  - _Depends: 2.2, 2.4, 4.1_

- [x] 5.3 FAQ管理画面のモードとアクセス制御を作る
  - 新規登録では質問・回答が空で登録操作が無効な状態を表示する
  - 編集では対象FAQが入力済みで保存操作が有効な状態を表示する
  - 一般社員には「権限がありません」を表示し、未認証利用者はログイン画面へ移動する
  - 管理者だけが指定された新規登録または編集モードを表示できることを完了条件とする
  - _Requirements: 5.1, 5.5, 5.9_
  - _Depends: 5.2_

- [x] 5.4 FAQの新規登録と入力境界を作る
  - 質問と回答にUnicode文字を受け付け、空白・改行だけの場合は登録を無効にする
  - 各1000書記素まで反映し、1001書記素目と画面制御を経由しない超過値を受け付けない
  - 有効な登録では「FAQを登録しました」を表示し、FAQモック状態へ新しい項目が保存されることを完了条件とする
  - _Requirements: 5.2, 5.3, 5.5, 5.6_
  - _Depends: 5.3_

- [x] 5.5 FAQの編集と完全一致競合を作る
  - 変更した内容と初期表示から変更のない内容のどちらも保存し、「FAQを修正しました」を表示する
  - 新規登録時の既存質問との完全一致、および編集時の対象外FAQとの完全一致では変更せず重複文言を表示する
  - 対象自身と同じ質問は保存でき、FAQモック状態が更新され、削除操作が存在しないことを完了条件とする
  - _Requirements: 5.4, 5.7, 5.8, 5.10_
  - _Depends: 5.4_

- [ ] 6. 画面とモック状態を利用者フローとして統合する
- [ ] 6.1 認証操作と共通ナビゲーションを接続する
  - 共通ナビゲーションのログアウト操作でセッションを終了し、ログイン画面へ移動してナビゲーションと社内情報を消す
  - セッション期限切れ後の画面移動でも同じ未認証状態へ移行する
  - 一般社員と管理者社員の全認証済み画面から一貫したログアウト・期限切れ結果になることを完了条件とする
  - _Requirements: 1.9, 1.11, 1.12, 7.2, 7.3, 7.4_
  - _Depends: 3.3, 4.1_

- [ ] 6.2 質問結果・評価と本人履歴を接続する
  - 回答完了と回答不能では質問、結果、質問日時を本人履歴へ追加し、生成失敗と中断では追加しない
  - 初回評価を対応する本人履歴へ反映し、他社員の履歴へ影響させない
  - 質問から履歴確認までの一連の操作で追加条件と評価が一貫して表示されることを完了条件とする
  - _Requirements: 3.1, 3.2, 3.4, 3.5, 6.3, 6.5_
  - _Depends: 4.3, 4.5, 5.1_

- [ ] 6.3 FAQ管理結果を閲覧画面と後続回答へ接続する
  - 登録・修正したFAQをFAQ閲覧画面へ反映し、同一ページセッション中の後続質問で回答根拠として利用する
  - 管理者の登録・編集導線と一般社員の非表示・拒否を一貫させる
  - FAQの登録または修正後、一覧と出典を含む後続回答に最新内容が現れることを完了条件とする
  - _Requirements: 2.2, 2.9, 4.1, 4.4, 5.1, 5.3, 5.4, 5.9, 7.3_
  - _Depends: 4.3, 4.4, 5.2, 5.4, 5.5_

- [ ] 7. モックアップ全体を自動検証する
- [ ] 7.1 認証・ロック・セッションの境界を統合テストする
  - 有効・無効な資格情報、失敗1〜5回、10分未満・ちょうど、成功時リセットを検証する
  - セッションの24時間未満・ちょうど、ログイン済みアクセス、保護画面、ログアウトを検証する
  - 一般社員と管理者社員の認証要件が実時間待機なしですべて合格することを完了条件とする
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 1.6, 1.7, 1.8, 1.9, 1.10, 1.11, 1.12, 1.13, 7.4_

- [ ] 7.2 質問・出典・評価・履歴を統合テストする
  - 0・1・400・401書記素、空白・改行、複合絵文字、ツールチップの表示と関連付けを検証する
  - 回答の順次表示、完了、回答不能、生成失敗、再試行、出典、履歴への保存条件を検証する
  - 完了後の一回評価と他社員から分離された履歴まで、対象要件が決定的に合格することを完了条件とする
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5, 2.6, 2.7, 2.8, 2.9, 2.10, 2.11, 2.12, 3.1, 3.2, 3.3, 3.4, 3.5, 6.1, 6.2, 6.3, 6.4, 6.5, 6.6_

- [ ] 7.3 FAQ閲覧・管理・権限を統合テストする
  - FAQの空状態と一覧、一般社員と管理者社員の表示差、管理画面のアクセス結果を検証する
  - 0・1・1000・1001書記素、新規登録、編集、無変更保存、完全一致競合を検証する
  - FAQ削除操作や対象外機能が存在せず、FAQ関連要件がすべて合格することを完了条件とする
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 5.1, 5.2, 5.3, 5.4, 5.5, 5.6, 5.7, 5.8, 5.9, 5.10, 7.1, 7.2, 7.3, 7.5_

- [ ] 7.4 モックアップの最終ビルドと禁止境界を検証する
  - 型検査、全自動テスト、本番ビルドを実行して成功させる
  - サーバールート、HTTP API通信、データベースクライアント、外部AI SDKが追加されていないことを依存関係とコードから確認する
  - ログインから始まる5画面がブラウザ内モックだけでビルドされ、主要フローを操作できることを完了条件とする
  - _Requirements: 7.1, 7.4, 7.5_
